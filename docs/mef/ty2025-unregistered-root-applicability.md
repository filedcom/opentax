# TY2025 unregistered-root applicability crosswalk

Static build-stage triage, 2026-09-28. The source is the checked-in
`ReturnData1040.xsd` document-root census in
[`ty2025-xsd-document-root-census.md`](ty2025-xsd-document-root-census.md),
compared with public inputs in `forms/f1040/2025/inputs.ts`, the node registry,
and `ALL_MEF_FORMS`. The historical unregistered-root review is grouped below;
the current census has 114 `No` rows. Schedules 1-A, J, LEP and R, Forms 2210-F,
2439/8888, W-2G, and Form 8995-A Schedules C/D are now-registered status notes,
not missing native roots. This is a **disposition queue**, not a completed
form-by-form coverage inventory. Neither a root's presence in the schema nor a
public input proves that it must be attached to every return. Conversely,
absence of a public input is not a user-approved exclusion.

The only currently agreed exclusions are standalone 1040-NR, 1040-SS, Form 4868,
and dual-status 1040 e-file. No additional path below is treated as excluded.
The conditional filing triggers and local gaps for Form 8995-A Schedules A-D and
Form 1116 Schedule C are audited separately in
[`ty2025-conditional-schedule-applicability.md`](ty2025-conditional-schedule-applicability.md).

`Applicable` means a real Form 1040 tax or filing situation can use the root and
needs implementation or an explicit fail-closed disposition. `Undecided` means
the source and required-attachment rules still need review.
`Likely separate-entity/administrative` is a proposed product boundary, **not**
permission to drop it. The team needs to confirm whether it must be attached to
an individual return, consumed only as source evidence, or handled in a separate
workflow.

## Entity-issued or entity-owned documents: likely separate-entity, not excluded

These are in `ReturnData1040.xsd` and may be transmitted with an individual
return or used as source evidence. Their primary form owner often differs from
the individual Form 1040 filer. That observation is **not** a determination that
the individual workflow may omit them.

The [entity-issued root disposition](ty2025-entity-issued-root-disposition.md)
separately classifies `IRS1065ScheduleD` and `IRS8825` as other-filer documents
for a K-1-only individual, and identifies the box 13 code B exception that
makes `IRS1041ScheduleK1` a required individual attachment. These are scoped
filing rules, not blanket exclusions or a completed source-to-return audit.

## Special census caveat

`IRS8839` was `No` in the static source-literal census because the registered
`form8839` descriptor currently fails closed before constructing native XML. It
is not an unregistered descriptor and not a supported adoption-credit path. The
active credit still needs source, calculation, MeF, PDF and validation work.
Similarly, a literal mention of `IRS8886` in a different descriptor does not
create a registered Form 8886 document. Registration must be checked against
`ALL_MEF_FORMS`, and all applicability classifications above remain subject to
the full source-to-filed-return inventory.
