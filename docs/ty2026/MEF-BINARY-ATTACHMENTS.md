# TY2026 MeF PDF binary attachment handoff

The TY2025 [`buildMefBundle`](../../forms/f1040/2025/mef/builder.ts) combines
caller-supplied PDFs with PDFs generated by four of the 85 runtime form
descriptors. It validates names, descriptions, size and PDF bytes, emits one
`BinaryAttachment` document per PDF, assigns document IDs after form documents,
and gives those IDs to the form serializers. The
[`submission archive`](https://github.com/filedcom/opentax/blob/b7c07b616564167a91bc588dba05caab2a28e054/forms/f1040/2025/mef/submission-archive.ts) writes
each PDF at `attachment/<fileName>`. This is a distinct surface from the 84
module public form crosswalk and the 56 IRS form PDF descriptors: a correct
2026 XML form can still omit a required binary or refer to the wrong one.

The four generators below are the complete `buildBinaryAttachments` set in
[`forms/f1040/2025/mef/forms`](../../forms/f1040/2025/mef/forms). The current
restricted TY2026 1040 XSD and business rules are the authority for final
binary document names, reference attributes and allowed content. The
[public workbook](corpus/mef/forms-attachments.xlsx) is an inventory, not a
binary specification. No TY2025 attachment rule should be copied on that
evidence alone.

## Caller-supplied binary path

`buildMefBundle` also accepts `options.attachments`; it places these before
generated PDFs and assigns their IDs in that order. TY2025 serializers can
reference such PDFs without generating them, for example a Form 3800 transfer
election statement or Form 8835 supporting statement. A 2026 form/statement
inventory therefore needs **both** generator ownership and caller-supplied
binary ownership. For each allowed binary in the selected 2026 package, record
the source input, filing trigger, owner form, PDF creation or upload path,
filename, description, XML reference and exclusion test. Reject a required
PDF that is missing; reject an orphan PDF when the package or business rule
forbids it. The 2025 `options.attachments` parameter is a code seam, not proof
that any particular PDF is allowed for 2026.

## Assembly checks

1. Freeze the selected 2026 XSD/rule release and list all accepted
   `BinaryAttachment`/general-dependency references, including new forms and
   externally supplied statements. Cross-check against every 2026 form
   descriptor and the public [crosswalk](MEF-PUBLIC-CROSSWALK.md).
2. Generate required PDFs from the same calculated source records used by
   XML and printable form output. For repeated forms or activities, pair by
   stable source identity before assigning sequential filenames and document
   IDs. Check no duplicate name or description, valid PDF bytes and size, and
   that each required reference resolves to exactly the intended PDF.
3. Validate the full XML plus attachment ZIP against the selected 2026
   package. Inspect `ReturnData@documentCnt`, `ReturnHeader` binary count,
   `AttachmentLocationTxt`, `referenceDocumentId`, ZIP `attachment/` entries,
   and the 2026 manifest year/period. Exercise zero, one and repeated binary
   cases. Local XML validation alone cannot prove the PDF content or IRS ATS
   acceptance.

No 2026 compatibility layer or TY2025 attachment fallback is proposed here.
