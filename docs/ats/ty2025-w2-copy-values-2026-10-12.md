## Matching and evidence boundaries

The observer reads the emitted `IRSW2` documents, preserving leading-zero TINs.
Employer name locates each copy, with case and whitespace normalization only;
both name lines are considered. Scenario 1 has two differently named employers
with the same EIN, so EIN alone would select an ambiguous source. XML document
order, wage amounts and recipient identity do not determine the match. SSN and
EIN are then checked independently on the selected copy.

Duplicate matching names produce ambiguous-copy observations even if the
copies are identical. Missing fields are never filled from another W-2, pending
data or Form 1040 totals. A missing copy does not imply false checkboxes.
On an existing copy, schema `CheckboxType` uses X for selected and absence for
unselected; invalid or repeated values are not matches. The selected fields and
line annotations were checked against the cached TY2025v5.4 IRSW2 schema and
common types, with file hashes retained.

All 30 evaluated fields match on the three currently emitted partial returns.
The 50 observations from preparation-blocked scenarios remain unevaluated,
separate from missing fields or copies. These checks do not verify addresses,
state/local rows, remaining W-2 fields, every possible employer-name collision,
PDF rendering, applicable IRS business rules or acceptance. The existing copy
presence counts remain a separate evidence category.
